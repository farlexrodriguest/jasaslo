# Riset editorial: Panduan dan Artikel Jasa SLO

> Disusun 18 Oktober 2026. Dokumen ini adalah **backlog dan pedoman editorial**, bukan penetapan persyaratan hukum. Verifikasi kembali regulasi, standar, biaya, masa berlaku, serta prosedur resmi sebelum menerbitkan setiap konten.

## 1. Pembedaan tipe konten

| Aspek | Panduan (`/panduan/`) | Artikel (`/artikel/`) |
|---|---|---|
| Maksud pencarian | "cara", "syarat", "dokumen", "tahapan", "persiapan", "checklist" | "apa itu", "mengapa", "perbedaan", "fungsi", "standar", "risiko" |
| Tujuan pembaca | Menuntaskan tugas atau menyiapkan pengajuan/pemeriksaan | Memahami konsep dan mengambil keputusan |
| Format | Langkah, checklist, prasyarat, hasil, kendala, FAQ | Penjelasan, perbandingan, contoh, referensi, FAQ |
| CTA | Layanan relevan setelah pengguna memahami langkah | Baca panduan terkait atau layanan terkait |
| Kebutuhan pembaruan | Tinggi ketika alur layanan berubah | Tinggi pada artikel regulasi/standar; sedang untuk konsep dasar |

**Aturan:** Satu pertanyaan utama = satu halaman utama. Jangan menerbitkan dua halaman yang menjawab maksud pencarian identik. Panduan dan artikel boleh saling merujuk, tetapi jangan menduplikasi isinya. Konten layanan (`/layanan/`) tetap berorientasi penawaran jasa, bukan menggantikan panduan atau artikel.

Gunakan `relatedType: service` dan `relatedId` berdasarkan **ID layanan yang benar dalam repository**, bukan menebak ID. Hubungkan artikel → panduan → layanan bila alurnya alami. CTA tidak boleh menyiratkan situs sebagai penerbit resmi sertifikat/izin.

## 5. Standar penulisan dan publikasi

1. **Satu search intent per halaman**: pertanyaan, target pembaca, dan langkah berikutnya jelas.
2. **Panduan**: tujuan, untuk siapa, prasyarat, checklist, langkah, hasil yang diharapkan, kendala umum, FAQ, referensi, CTA relevan.
3. **Artikel**: jawaban ringkas di awal, definisi/penjelasan, perbandingan atau contoh, batasan, FAQ, referensi, tautan ke panduan.
4. **Frontmatter**: gunakan schema `src/content.config.ts`; ID/ULID unik, slug kebab-case, tanggal valid, `blocks` sesuai komponen yang didukung.
5. **Kualitas sumber**: utamakan ESDM/Gatrik, JDIH ESDM, PLN, BSN, IEC. Sertakan tanggal akses dan tanggal peraturan; periksa apakah aturan masih berlaku.
6. **YMYL/keselamatan**: hindari janji “pasti terbit”, estimasi biaya/durasi tanpa sumber, klaim masa berlaku universal, atau panduan pengoperasian peralatan bertegangan oleh awam.
7. **SEO**: hindari kanibalisasi dengan halaman layanan; judul unik, deskripsi spesifik, tautan internal dua arah, pembaruan jika prosedur berubah.
8. **QA**: `npm run validate:content` lalu `npm run build`; tinjau hasil render block dan CTA secara visual.
